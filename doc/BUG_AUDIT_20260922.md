## 🔴 高危 —— 数据丢失 / 错误结果

### 主线（生产路径）

#### R1. 人工 √/× 标签被静默清空 ☐
- **位置**：`services/detection.py:453-461`（`_persist_marks`），触发点 `:1513-1516`（卡片标记）、`:2101`（历史加载 `_sync_marks`）
- **触发条件**：clips 是 goals 的真子集（预览切片部分失败，或片段被 7 天清理后重生成不完整），且历史里存在**不在 clips 上**的人工标记 → 用户任点一次 √/× 或加载历史即触发。
- **根因**：`write_manual=True` 时用「当前 clips 上的标记」**整体替换**历史 kept/deleted，不在 clips 上的 ts 被当作"无标记"抹掉。重检测路径已用 `write_manual=False` 规避（`:445-448` 注释自证替换语义），但历史加载与卡片标记两条路径没防。
- **修法方向**：替换语义改为合并语义（保留不在 clips 上的旧 ts），或替换前把历史中不在本次 clips 里的 ts 原样带回。

#### R2. 刷新页面 → 断点被误删 ☐
- **位置**：`demo_nicegui.py:1054-1063`
- **触发条件**：断点续跑对话框弹出后，用户刷新页面 / 浏览器断开。
- **根因**：对话框 `persistent` 禁止 ESC/遮罩关闭，但断连时 `await dlg` 返回 **None**；`if not _resume_choice` 把 None（外因关闭）与 False（用户选"从头开始"）同等处理 → `delete_checkpoint(vp)` 删光该视频全部断点，几十分钟进度静默丢失。
- **修法方向**：`if _resume_choice is None: return`（外因关闭 ≠ 用户选择）。

#### R3. 检测/批量运行中刷新页面 → 任务收尾全丢 ☐
- **位置**：`demo_nicegui.py:1120/:943`（`clear_live` 只写在原页面协程里），对比 `:1527`（流水线分支已放 finally）
- **触发条件**：检测或批量运行期间刷新页面，后台线程继续跑完。
- **现象**：live 进度槽永不清空 → `_sync_live_ui`（:1808-1848）只在槽为 None 时复位，新页面按钮永显"取消"、进度停格；进球卡片不出现，显示"暂无结果"与历史已落盘矛盾；此时点"取消"因锁已释放走启动分支 → **整场重检**。
- **修法方向**：所有分支把 `clear_live` 收进 finally（或收尾统一在后台线程侧完成，不依赖页面协程存活）。

#### R4. 混合编码器 concat 花屏风险 ☐
- **位置**：`cutter/ffmpeg_cutter.py:320-364`（回退逻辑）+ `:399-438`（concat 流拷贝）
- **触发条件**：第 k 段 NVENC 运行时失败/超时回退 libx264 后，0..k-1 段为 h264_nvenc（main profile）、其余为 libx264（high profile）；`concat -c copy` 不校验参数差异，MP4 只写首段 avcC/SPS → 后半段按错误 SPS 解码，静默花屏风险。
- **实际风险**：本机 GTX 1650 无 NVENC 单元、首段即整体回退，触发概率低；且 copy 失败有整体 re-encode 兜底。但逻辑漏洞存在。
- **修法方向**：任一段发生 NVENC 回退时打标记，导出路径跳过 `-c copy` 直接走 re-encode。

### 训练侧（污染线上模型）

#### R5. eval_thresholds 循环评估 ☐
- **位置**：`training/eval_thresholds.py:34`；口径源头 `services/state.py:834-847`
- **触发条件**：用 `state.label_sets`（**人工 ∪ 模型** 口径）当 ground truth 评模型分数。
- **根因**：模型 auto √ 的片段自动成 TP → AUC/精确率虚高 → keep_thr 标定被误导。`label_sets` 的 docstring 自己写明"需要严格只用人工标签时请显式只取 kept/deleted"，而 eval_thresholds 没这么做，且其 docstring 自称"人工标签"与实现不符。
- **修法方向**：改用 `labels["kept"] / labels["deleted"]`（严格人工口径）。

#### R6. train_lgbm 无备份覆盖生产 A 臂模型 ☐（已知遗留，待决策）
- **位置**：`training/train_lgbm.py:144,171`（MODEL_FILE/META_FILE 即 goal_verifier 现役文件）
- **风险**：直接 `save_model`/`write_text` 覆盖线上模型，无备份、无确认、不校验 features.jsonl 完整性；残缺/陈旧特征也静默换掉线上模型。且 mtime 进 `model_fingerprint` → invalidate_stale 作废全量旧分，触发每候选 ~6.5s 的 A 臂重打分。
- **修法方向**（待决策）：训练写候选文件 + 显式 `--promote` 开关才覆盖生产，覆盖前自动备份。

#### R7. export 不作废已抽特征 → 改标后重训用旧标签 ☐（已知遗留，待决策）
- **位置**：`training/annotate.py:449-523`（export 覆盖写 dataset_v1.json）+ `training/extract_features.py:342-351`（断点续跑按 event_id 跳过）
- **根因**：features.jsonl 的 label 冻结在首次提取时，改标后重训 train_lgbm 仍用旧标签。续跑键只含 event_id，无 label/特征版本指纹。
- **修法方向**（待决策）：续跑键加入 label 指纹（或 export 时同步改写 features.jsonl 对应行）。

#### R8. annotate.py 导入名错误 → 永远走兜底编码参数 ☐
- **位置**：`training/annotate.py:125`
- **根因**：`from cutter.ffmpeg_cutter import _build_encode_args` —— 实际函数名是 `build_encode_args`（无下划线）→ ImportError → except 硬编码兜底 `["-c:v","libx264","-preset","veryfast","-crf","28","-an"]`：无 `-pix_fmt yuv420p`、无 HDR→SDR 映射 → HDR 10bit 源标注片段编出 High10、浏览器播不出；且与预览切片参数口径漂移。
- **修法**：一行改名。已验证属实。

#### R9. 指纹不含实际臂组合 → 缺臂降级分数冒充全量口径 ☐（已知遗留，待决策）
- **位置**：`services/goal_verifier.py:404-416`（指纹只哈希模型文件 mtime+权重+keep_thr）+ `:706-715`（combine 缺臂重归一化）+ `:95/:166/:298`（`_tried` 闩死不重试）
- **触发条件**：VM 臂 HF 缓存丢失/依赖缺失，或 B/Flow 一次加载失败（GPU OOM、文件被杀软占用等瞬时故障整进程闩死缺臂）。
- **风险**：2-3 臂重归一化分数与四臂全量分数算出**同一 verify_ver**；臂恢复后 invalidate_stale 判"口径未变"不重算，refresh_auto 沿用降级分数分带；阈值按全组合 OOF 标定 → 缺臂组合沿用即口径错配 → 低带误 × 漏球、高带误 √ 固化进训练集。
- **修法方向**（待决策）：指纹加入本次实际参与的臂组合；`_tried` 对瞬时异常允许一次重试。
