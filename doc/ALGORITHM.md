# 进球检测算法详解

## 进球检测算法详解

---

### 可调参数

| 分区 | 参数 | 默认值 | 说明 |
|------|------|--------|------|
| **顶部开关** | 提速模式 | **开（每 3 帧）** | YOLO 每 3 帧推理一次，提速 ~27%，当前实测零漏检 |
| **顶部开关** | 条件跳过 | **开** | 筐区无「值得看一眼」的运动时跳过 YOLO。判据与运动斑块检测器**同构**（同一套二值化 + 同一套形态学 + 连通域 ≥ 最小斑块面积），由此保证「斑块可能触发 ⇒ YOLO 必已跑过」；跳过率随场次波动很大（近期实测 26%~94%） |
| 基础 | 球检测置信度 | **0.15** | YOLO 检测球的置信度阈值，降低可提升检出率 |
| 基础 | 最小进球间隔 | **2 秒** | 两个进球间的最小时间间隔（冷却期），防止重复计数 |
| 基础 | 起始帧 / 结束帧 | 0 / 0（末尾） | 只处理指定区间，跳过开场跳球或休息段 |
| 高级 | 自适应阈值 | 开 | 前 30 秒预热统计 P95 中位数 → 自动计算帧差阈值（推荐） |
| 高级 | 帧差阈值 | 15 | 手动覆盖模式下生效；低=灵敏，高=严格 |
| 高级 | 最小斑块面积 | 30 | 过滤小噪声；值越小越灵敏，可能引入细碎假信号 |
| 高级 | 搜索范围 | 80px | 篮筐周边搜索运动物体的范围（外扩像素） |
| 高级 | 圆形度阈值 | 0.35 | 过滤长条形人体；篮球≈0.7-1.0，0=禁用 |
| 高级 | 进框最少帧数 | 2 | 斑块进框连续多少帧才算候选，过滤瞬时噪声 |
| 集锦 | 提前 / 延后 | 5s / 5s | 每个进球片段向前/向后多剪的时间 |
| 集锦 | 合并间隔 | 8 秒 | 相邻片段间隔小于此值则自动合并 |

> **推理范围与分辨率不是 UI 参数**：只推「筐接受框 + 20% 外扩」（各场实测约 500×580），`imgsz` 固定 **640**。相比整帧 1920×1080 送 1280：像素量降到约 1/4（单场实测耗时 −34%），球在输入里反而更大（~22-33px vs ~13-20px），区域外的远端误报也天然落在输入之外。
>
> 裁剪范围必须 ⊇ `GoalDetector.yolo_accept_box()`（横向 ±1.5 倍筐宽、向上 1.0 倍、向下 2.0 倍筐高），否则会重现「球在筐附近、却不在推理输入里」的静默漏检。
>
> **已知风险**：把裁剪出的小图单独送进模型，会让部分小球的置信度掉到阈值以下、偶发整球没有候选（2026.08.31-3rd `449.16s` 实测，用户确认为真进球）。原因、证据链与可调参数实测见 [BENCHMARKS.md](BENCHMARKS.md) 的「③ 裁剪推理的已知漏检风险」。

### 标定口径：框住的是「篮筐 + 篮网」

UI 上「点 2 个点」标定的是**篮筐 + 篮网**这一整块，不是只筐圈（上沿对齐篮筐、下沿包到网底）。这个框有两处硬用途，画小了会直接影响检出：

- **进球状态机**：斑块的「筐上方 → 进框 → 筐下方」全部以框边界判定，且球要在框内连续停留「进框最少帧数」（默认 2，实测球在框内 2~4 帧）才算候选——只框筐圈时球一帧就穿过去了
- **YOLO 接受范围**：以框宽高为基准外扩（横向 ±1.5 倍框宽、向上 1.0 倍、向下 2.0 倍框高），并据此决定裁剪推理的输入范围（见上文「推理范围与分辨率」）

实测 27 场标定的框在 1080p 下约 **100 × 110 px**（高略大于宽、约占画面高 8%~12%），可作参考。
