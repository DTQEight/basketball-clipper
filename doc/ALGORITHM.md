# 进球检测算法详解

## 进球检测算法详解

---

### 可调参数

| 分区 | 参数 | 默认值 | 说明 |
|------|------|--------|------|
| **顶部开关** | 提速模式 | **开（每 3 帧）** | YOLO 每 3 帧推理一次，提速 ~27%，当前实测零漏检 |
| **顶部开关** | 条件跳过 | **开** | 筐区无「值得看一眼」的运动时跳过 YOLO。判据与运动斑块检测器**同构**（同一套二值化 + 同一套形态学 + 连通域 ≥ 最小斑块面积），由此保证「斑块可能触发 ⇒ YOLO 必已跑过」；跳过率随场次波动很大（近期实测 26%~94%） |
| 基础 | 球检测置信度 | **0.15** | YOLO 检测球的置信度阈值，降低可提升检出率 |
| 基础 | 最小进球间隔 | **2 秒** | 两个进球间的最小时间间隔（冷却期），防止重复计数 |
| 基础 | 起始帧 / 结束帧 | 0 / 0（末尾） | 只处理指定区间，跳过开场跳球或休息段 |
| 高级 | 自适应阈值 | 开 | 前 30 秒预热统计 P95 中位数 → 自动计算帧差阈值（推荐） |
| 高级 | 帧差阈值 | 15 | 手动覆盖模式下生效；低=灵敏，高=严格 |
| 高级 | 最小斑块面积 | 30 | 过滤小噪声；值越小越灵敏，可能引入细碎假信号 |
| 高级 | 搜索范围 | 80px | 篮筐周边搜索运动物体的范围（外扩像素） |
| 高级 | 圆形度阈值 | 0.35 | 过滤长条形人体；篮球≈0.7-1.0，0=禁用 |
| 高级 | 进框最少帧数 | 2 | 斑块进框连续多少帧才算候选，过滤瞬时噪声 |
| 集锦 | 提前 / 延后 | 5s / 5s | 每个进球片段向前/向后多剪的时间 |
| 集锦 | 合并间隔 | 8 秒 | 相邻片段间隔小于此值则自动合并 |

> **推理范围与分辨率不是 UI 参数**：只推「筐接受框 + 20% 外扩」（各场实测约 500×580），`imgsz` 固定 **640**。相比整帧 1920×1080 送 1280：像素量降到约 1/4（单场实测耗时 −34%），球在输入里反而更大（~22-33px vs ~13-20px），区域外的远端误报也天然落在输入之外。
>
> 裁剪范围必须 ⊇ `GoalDetector.yolo_accept_box()`（横向 ±1.5 倍筐宽、向上 1.0 倍、向下 2.0 倍筐高），否则会重现「球在筐附近、却不在推理输入里」的静默漏检。
>
> **两段式兜底（2026.09.21）**：裁剪档在小球上会把置信度系统性压低，整窗一帧都不过阈值的事件会静默漏掉（2026.08.31-3rd `449.16s`，用户确认为真进球）。因此默认仍走裁剪@640，只在某条轨迹**即将被 YOLO 硬否决**（整窗无球证据）时，用 `YOLO_PROBE_MODE='mask'`（抹黑画布@1280）在当前帧补检一次，且只采信 `conf ≥ YOLO_PROBE_CONF`（默认 0.5）的证据。6 场实测真球 **116/119 → 119/119**，误报 +3、候选 +8.8%，补检本身约占耗时 1.7%。
>
> 为什么不全局换档：全局抹黑@1280 真球净只 +1，却要 **+14.5% 检测耗时、候选 +13%**（事件级召回对单帧分数不敏感——状态机只要窗口里有一帧过阈值就够）。完整 A/B 与挖矿数据见 [BENCHMARKS.md](BENCHMARKS.md)。

> **静止球证据门（2026.09.21）**：`_check_yolo_near_hoop` 只问「±0.34s 窗口内有没有球」，**对球证据没有任何运动性要求**。于是筐接受框内一旦有个被模型认成球的**静止**物体（墙上横幅的圆形 logo、标志牌上的球状图案），它每帧都会被重新检出 → 硬否决长期失效 → 筐区任何运动斑块都被确认成进球（2026.09.21-4th 实测：281~368s 连出 39 个误报，人工标了 35 个 ×）。
>
> 故球证据需先过 `GoalDetector._drop_static_balls()`：球心量化到 `STATIC_BALL_TOL_PX`（12px）网格，同一格在 `STATIC_BALL_SEC`（1.0s）内被持续检出即判为静止物、不作证据；中断超过 `STATIC_BALL_GAP_SEC`（2.0s）则重新计时。主检测路径与两段式补检路径**都过这道门**（备用档同样会把海报认成球）。真球在筐区不可能原地不动 ≥1 秒，双盲测日 5 场真球一个没掉（候选也几乎不变，门在场次无静止假球时是 no-op）；采集日志非零时多一行 `静止剔除: N 条球证据被判为静止物体`。

> **已知代价**：换用「按部署几何重训」的球检测权重（2026.09.21）后，抹黑画布档在正常帧的命中率从 90% 降到 79%（≥0.2 口径仅 96%→95%）。生产主档是裁剪@640、兜底有 `conf` 门槛，端到端未暴露；但**调 `YOLO_PROBE_CONF` 前必须重测这一项**。详见 [BENCHMARKS.md](BENCHMARKS.md)「篮球检测权重三代对比」。

### 标定口径：框住的是「篮筐 + 篮网」

UI 上「点 2 个点」标定的是**篮筐 + 篮网**这一整块，不是只筐圈（上沿对齐篮筐、下沿包到网底）。这个框有三处硬用途，画小了会直接影响检出：

- **进球状态机**：斑块的「筐上方 → 进框 → 筐下方」全部以框边界判定，且球要在框内连续停留「进框最少帧数」（默认 2，实测球在框内 2~4 帧）才算候选——只框筐圈时球一帧就穿过去了
- **AI 三臂裁剪**：以框中心为中心、短边 = **3.2 × 框高**；框画小了裁剪窗跟着缩，视觉特征与训练口径错位
- **YOLO 接受范围**：以框宽高为基准外扩（横向 ±1.5 倍框宽、向上 1.0 倍、向下 2.0 倍框高）

实测 27 场标定的框在 1080p 下约 **100 × 110 px**（高略大于宽、约占画面高 8%~12%），可作参考；[recover_hoop2.py](../training/recover_hoop2.py) 反推丢失标定时取的统计中位正是「高 = 0.09 × 视频高」。

### AI 复核（四臂集成打分）

检测出候选后自动跑一遍四臂集成，给每个候选打 0~1 的分；达到阈值的直接标 √，人工确认时可不逐个点。**只标记、不删除任何候选**——低分候选照常进入人工确认，因此不会造成额外漏球。

| 臂 | 输入 | 模型 | 权重 |
|---|---|---|---|
| A | 候选 ±1.5s 逐帧 YOLO 复检 → 35 维手工特征 | LightGBM | 0.5 |
| B | 筐心 16 帧块（彩色） → 域内自监督 SimCLR resnet18 特征 | bigru + pool 双时序头取均值 | 2.0 |
| Flow | 筐心 16 帧 → Farneback 光流幅度序列（15 帧） | 光流域自监督 SimCLR resnet18 + bigru | 1.0 |
| VM | 筐心 16 帧块 | VideoMAE v2 768 维 → LightGBM | 1.0 |

集成分 = 各臂 sigmoid 概率按权重加权平均，**缺臂时按剩余权重重归一化**（只剩一臂可用时退化为该臂分）。权重与阈值**不是 UI 参数**，读自 `training/model_temporal_meta.json` 的 `ensemble` 段（由离线标定流程写在 OOF 上确定；当前 `keep_thr = 0.68`）。

> B 与 Flow 两臂的骨干都是**域内自监督**（SimCLR 对比学习，不利用标签）：B 在筐心彩色帧上预训练，Flow 在光流幅度图上预训练。这是刻意分开的——光流图是灰度运动边缘图，与彩色帧分布相差很远，彩色域编码器提不出有意义的特征。`ImageNet` 骨干只在对应 checkpoint 缺失时作为兜底。

**裁剪口径必须与训练完全一致**（错位会直接毁掉三个视觉臂）：以篮筐中心为中心，短边 = 3.2 × 筐高，越界填灰 114，等比缩放到 224；16 帧偏移为 `-1.5 … +1.4s`（穿筐瞬间密采）。服务端直接 import 训练侧的 `crop_hoop` 与 `FRAME_OFFS`，不另写一份。归一化按臂区分：

| 臂 | 归一化 |
|---|---|
| B（SimCLR） | BGR→RGB，/255，**不做** mean/std（编码器是在裸 /255 上自监督训出来的） |
| Flow（SimCLR） | 光流幅度 /255，**不做** mean/std（三通道相同，无通道序问题） |
| Flow（ImageNet 兜底） | BGR→RGB，/255，再做 ImageNet mean/std |
| VM | BGR→RGB，(x/255 − 0.5) / 0.5 |

**三段分诊（自动标记规则）**：集成分按两个阈值分成三带，人工只需复核**中间带**。

| 带 | 条件 | 自动动作 |
|---|---|---|
| 高带 | `score >= keep_thr`（0.68） | `mark=keep`、`mark_source=auto` → 卡片绿标「AI ✓」，可直接跳过 |
| 中间带 | `reject_thr <= score < keep_thr` | 不加任何标记 → 琥珀标「AI ?」，**这是唯一需要人看的带** |
| 低带 | `score < reject_thr`（0.15） | `mark=reject`、`mark_source=auto` → 卡片红标「AI ×」，可直接跳过 |

为什么不追「全部自动 √」：9 场 419 片子实测，要 100% 召回得把阈值压到 **0.152**，那时精度只有 **0.602**（259 个自动√里 103 个是误报）——自动判定就失去意义了。根因是**最高误报分 0.781 之下压着 44.9% 的真球**，两个分布重叠，靠调阈值挪不开；而且各场「最低真球分」从 0.152 到 0.670 跨了 0.52，单点全局阈值不可能同时适配。三段分诊把这个矛盾拆开：高带阈值管误报、低带阈值管漏球，人工成本从「逐个过 419 个」降到「只看 132 个（31%）」，且一个球不漏。

**人工标记永远优先**——`mark_source == "manual"` 的片段不会被自动标记覆盖（用户判过的 × 不会因为模型给高分被翻成 √），阈值调高后落回中间带的片段会被清掉模型标记交还人工。换模型 / 调权重 / 改阈值（`keep_thr`）后，分数会被**口径指纹**（模型文件 mtime + 权重 + 阈值 的哈希）判定失效并重算，避免「新阈值套旧分」；`reject_thr` 不进指纹——它只影响标记不影响分数，`refresh_auto` 会按缓存分重推。

**AI 识别总开关**：UI「参数 → AI 识别（四臂复核）」可整体关闭复核（`goal_verifier.set_enabled`）。关闭后检测不跑四臂（省掉 A 臂逐帧 YOLO 的数分钟开销），候选不带分数与自动标记、全部留人工判定；历史回读也不触发补跑或重推阈值。关闭只是「不再跑」——缓存分数与历史标签都不动，重开开关即时从缓存分恢复三带分诊，无需重算。

**历史回读前先问**：开关开着、但这条历史记录的片段缺分数时（旧记录／当初关着开关跑出来的记录／片段缓存失效要重新生成），加载前会弹窗确认「补跑 AI / 直接加载」，避免静默跑分钟级复核。判断走 `detection.history_missing_scores`，只读历史记录与片段缓存，不生成预览、不碰 GPU、秒回。批量回看不问：那里的分数由检测 / 批量识别产生，缺分就缺分（要补分去历史记录里加载该视频）。

> ⚠️ 标签库按来源分流（人工 / 模型各存各的，两侧对称）：人工 √/× 进 `labels.kept`/`labels.deleted`；模型自动 √/× 进 `labels.auto_kept`/`labels.auto_rejected`。混在一起会形成「模型自己判→自己学」的闭环，也看不出「模型替人省了多少」。**导出与评估**走「人工 ∪ 模型」口径（`state.label_sets`）——只看 kept/deleted 会把模型自动 √ 当成未标注，直接变成假阴性、整场丢球；**重建训练集**（`build_dataset.py`）负样本只读人工 ×，正样本取人工 ∪ 模型并打 `label_source`（`ui_manual` / `ui_auto`）以区分来源。

> ⚠️ 绝对阈值不跨场稳定：`2026.09.03-3rd`（6.3 分钟短片段）排序完美（AUC 1.0）但所有视觉臂绝对分整体偏低 0.2~0.6，阈值下一个都过不了。详见 [CHANGELOG.md](CHANGELOG.md#20260919-四臂集成-ai-复核自动-) 的「已知边界」。

> ⚠️ OOF 阈值与实测口径有差距：阈值在 831 事件 OOF 上按 p95 工作点标定，但 OOF 的 p95 阈值（0.640）放到 6 场真实录像上会放进 2 个误报（精度 0.976），最终部署取了更保守的 `0.68`（实测精度 0.988 / 召回 80.6%）。真实视频目前只有 6 场，单个视频里 3 个片段的分数翻转就能左右「零误报召回」这类指标——判断模型好坏要看 AUC，不要用这类阈值敏感的指标下结论。
