# 进球检测算法详解

## 进球检测算法详解

---

### 可调参数

| 分区 | 参数 | 默认值 | 说明 |
|------|------|--------|------|
| **顶部开关** | 提速模式 | **开（每 3 帧）** | YOLO 每 3 帧推理一次，提速 ~27%，当前实测零漏检 |
| **顶部开关** | 条件跳过 | **开** | 筐区无「值得看一眼」的运动时跳过 YOLO。判据与运动斑块检测器**同构**（同一套二值化 + 同一套形态学 + 连通域 ≥ 最小斑块面积），由此保证「斑块可能触发 ⇒ YOLO 必已跑过」；跳过率随场次波动很大（近期实测 26%~94%） |
| 基础 | 球检测置信度 | **0.15** | YOLO 检测球的置信度阈值，降低可提升检出率 |
| 基础 | 最小进球间隔 | **2 秒** | 两个进球间的最小时间间隔（冷却期），防止重复计数 |
| 基础 | 起始帧 / 结束帧 | 0 / 0（末尾） | 只处理指定区间，跳过开场跳球或休息段 |
| 高级 | 自适应阈值 | 开 | 前 30 秒预热统计 P95 中位数 → 自动计算帧差阈值（推荐） |
| 高级 | 帧差阈值 | 15 | 手动覆盖模式下生效；低=灵敏，高=严格 |
| 高级 | 最小斑块面积 | 30 | 过滤小噪声；值越小越灵敏，可能引入细碎假信号 |
| 高级 | 搜索范围 | 80px | 篮筐周边搜索运动物体的范围（外扩像素） |
| 高级 | 圆形度阈值 | 0.35 | 过滤长条形人体；篮球≈0.7-1.0，0=禁用 |
| 高级 | 进框最少帧数 | 2 | 斑块进框连续多少帧才算候选，过滤瞬时噪声 |
| 集锦 | 提前 / 延后 | 5s / 5s | 每个进球片段向前/向后多剪的时间 |
| 集锦 | 合并间隔 | 8 秒 | 相邻片段间隔小于此值则自动合并 |

> **推理范围与分辨率不是 UI 参数**：只推「筐接受框 + 20% 外扩」（各场实测约 500×580），`imgsz` 固定 **640**。相比整帧 1920×1080 送 1280：像素量降到约 1/4（单场实测耗时 −34%），球在输入里反而更大（~22-33px vs ~13-20px），区域外的远端误报也天然落在输入之外。
>
> 裁剪范围必须 ⊇ `GoalDetector.yolo_accept_box()`（横向 ±1.5 倍筐宽、向上 1.0 倍、向下 2.0 倍筐高），否则会重现「球在筐附近、却不在推理输入里」的静默漏检。
>
> **两段式兜底（2026.09.21）**：裁剪档在小球上会把置信度系统性压低，整窗一帧都不过阈值的事件会静默漏掉（2026.08.31-3rd `449.16s`，用户确认为真进球）。因此默认仍走裁剪@640，只在某条轨迹**即将被 YOLO 硬否决**（整窗无球证据）时，用 `YOLO_PROBE_MODE='mask'`（抹黑画布@1280）在当前帧补检一次，且只采信 `conf ≥ YOLO_PROBE_CONF`（默认 0.5）的证据。6 场实测真球 **116/119 → 119/119**，误报 +3、候选 +8.8%，补检本身约占耗时 1.7%。
>
> 为什么不全局换档：全局抹黑@1280 真球净只 +1，却要 **+14.5% 检测耗时、候选 +13%**（事件级召回对单帧分数不敏感——状态机只要窗口里有一帧过阈值就够）。完整 A/B 与挖矿数据见 [BENCHMARKS.md](BENCHMARKS.md)。

> **静止球证据门（2026.09.21）**：`_check_yolo_near_hoop` 只问「±0.34s 窗口内有没有球」，**对球证据没有任何运动性要求**。于是筐接受框内一旦有个被模型认成球的**静止**物体（墙上横幅的圆形 logo、标志牌上的球状图案），它每帧都会被重新检出 → 硬否决长期失效 → 筐区任何运动斑块都被确认成进球（2026.09.21-4th 实测：281~368s 连出 39 个误报，人工标了 35 个 ×）。
>
> 故球证据需先过 `GoalDetector._drop_static_balls()`：球心量化到 `STATIC_BALL_TOL_PX`（12px）网格，同一格在 `STATIC_BALL_SEC`（1.0s）内被持续检出即判为静止物、不作证据；中断超过 `STATIC_BALL_GAP_SEC`（2.0s）则重新计时。主检测路径与两段式补检路径**都过这道门**（备用档同样会把海报认成球）。真球在筐区不可能原地不动 ≥1 秒，双盲测日 5 场真球一个没掉（候选也几乎不变，门在场次无静止假球时是 no-op）；采集日志非零时多一行 `静止剔除: N 条球证据被判为静止物体`。

> **已知代价**：换用「按部署几何重训」的球检测权重（2026.09.21）后，抹黑画布档在正常帧的命中率从 90% 降到 79%（≥0.2 口径仅 96%→95%）。生产主档是裁剪@640、兜底有 `conf` 门槛，端到端未暴露；但**调 `YOLO_PROBE_CONF` 前必须重测这一项**。详见 [BENCHMARKS.md](BENCHMARKS.md)「篮球检测权重三代对比」。

### 标定口径：框住的是「篮筐 + 篮网」

UI 上「点 2 个点」标定的是**篮筐 + 篮网**这一整块，不是只筐圈（上沿对齐篮筐、下沿包到网底）。这个框有两处硬用途，画小了会直接影响检出：

- **进球状态机**：斑块的「筐上方 → 进框 → 筐下方」全部以框边界判定，且球要在框内连续停留「进框最少帧数」（默认 2，实测球在框内 2~4 帧）才算候选——只框筐圈时球一帧就穿过去了
- **YOLO 接受范围**：以框宽高为基准外扩（横向 ±1.5 倍框宽、向上 1.0 倍、向下 2.0 倍框高），并据此决定裁剪推理的输入范围（见上文「推理范围与分辨率」）

实测 27 场标定的框在 1080p 下约 **100 × 110 px**（高略大于宽、约占画面高 8%~12%），可作参考。
